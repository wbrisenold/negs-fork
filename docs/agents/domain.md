# Domain documentation

This repository uses a single-context domain model.

## Before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read relevant decisions in `docs/adr/` when that directory exists.
- If those files are absent, proceed without treating their absence as a blocker. Add domain terms or decisions when they are resolved through domain-modeling work.

## Vocabulary

Use the glossary's terms in issue titles, design proposals, hypotheses, and tests. If a required term is missing, record that gap rather than introducing an unreviewed synonym.

## Architecture decisions

Surface conflicts with relevant ADRs instead of silently overriding them.
